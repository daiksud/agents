## ランタイムとランナー

JavaScript アクションの `runs.using` は、アクション内部のランタイムを表す。`setup-node` の `node-version` やアプリケーションの `engines` が指定するプロジェクトの実行環境とは別に扱う。内部ランタイムの警告だけを理由に、プロジェクトの Node.js やロックファイルを更新しない。

更新先は実際に使うランナーのバージョン、OS、アーキテクチャ、GitHub.com・GitHub Enterprise Server の対応範囲と互換性があるものを選ぶ。

## バージョン更新

- 公式の安定リリースから互換性のある更新先を選び、バージョンコメントと参照先を一致させる。古い例の SHA や固定された推奨メジャーバージョンをそのまま採用しない。
- 入力・出力・既定値・認証・キャッシュ・成果物の互換性を保つ。内部ランタイムだけの変更でも、アクション全体の動作が同じとは限らない。
- 複合アクションや再利用可能なワークフローの内部を含め、更新が必要な参照を小さな単位でそろえる。互換性の条件が違う呼び出し元まで一律に更新しない。
- 環境変数で警告を隠すことや、アクションが対応していない `runs.using` を宣言することを恒久対策にしない。
