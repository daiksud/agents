# Root-Cause Analysis（根本原因分析）

欠陥の修正を手がかりに、どの条件で誤りが生じ、どの確認をすり抜けたかをたどる。障害の時系列、報告された入力、配備時の状態から仮説を立て、再現できるか試す。「担当者が見落とした」で調査を閉じると、次の担当者も同じ条件で失敗しうる。原因が複数あれば、同種の失敗を減らせ、効果を試せる対策から選ぶ。[テストファーストプログラミング](../primary-practices/test-first-programming.md)

## 二重送信が利用者に届いた経路をたどる

確認メールが二通届いたなら、送信自体は成功して応答だけが遅れ、再試行が同じ申込をもう一度処理した可能性を調べる。そうなら、その順序を再現するテストを作り、同じ申込では一通だけ届くように直す。正常応答しか返せない既存のテスト環境にも着目し、タイムアウトを起こせるようにする。次に同じ条件を与えて重複を検出できるか、修正後の処理で一通に留まるかをそれぞれ確かめる。
