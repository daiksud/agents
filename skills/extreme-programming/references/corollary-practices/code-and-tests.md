# Code and Tests（コードとテスト）

動作を決める規則はコードに表し、外から見て何を保証するかは実行できるテストに残す。同じ規則を設計表や手順書にも細かく転記すると、変更のたびにどれが現行かを調べる負担が生じる。検討用の図は相談に使い、実装後も読む人と用途がある資料を保守する。運用担当者が必要とする復旧手順など、コードを読んでも作業の順序が分からない情報には文書の役割がある。[テストファーストプログラミング](../primary-practices/test-first-programming.md)

## 境界額をテストから読めるようにする

注文額5,000円から送料が無料になるなら、4,999円と5,000円の注文を入力し、それぞれの送料を明示して検証する。期待値は合意した金額から決める。テスト内でも本体と同じ分岐で計算すると、境界を誤って動かしたときに双方が同じ答えを出してしまう。次に規則を改定する人が、この二例を読んで変更の影響を説明できるか確かめる。
