# Single Code Base（単一のコードベース）

一つの製品で継続して提供する振る舞いを、共通のコードベースで育てる。顧客ごとに長期の派生版を維持すると、一方の不具合修正が他方にも必要かを毎回調べることになる。共通の製品として扱う範囲を確認し、一時的な開発ブランチの変更は小さいうちに統合する。[継続的インテグレーション](../primary-practices/continuous-integration.md)

## 顧客ごとの違いを具体例から切り出す

二社向けの請求書で締め日だけが異なり、端数処理は共通だとする。両社で実際に使う請求例をテストにし、締め日を契約条件として渡せば、共通の端数処理を一か所で直せる。すべての差を一度に設定項目にすると、提供していない組み合わせまで保守する負担が増す。次の不具合修正を両社の例で実行できるか、片方だけへの修正の移植が残っていないかを見て、統合範囲を調整する。
