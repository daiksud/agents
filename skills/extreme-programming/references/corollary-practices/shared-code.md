# Shared Code（コードの共有）

チームの誰でも、自分が取り組むストーリーに必要な箇所を改善できるようにする。担当範囲が固定されていると、数行の修正でも受け渡しが発生し、呼び出し側に回避策が増えてしまう。意図を読み取れるテスト、小さな統合、詳しい人と調べられる関係があれば、初めて触る人も影響を確かめながら直せる。[ペアプログラミング](../primary-practices/pair-programming.md)

## 二つの入口で同じ料金規則を使う

窓口とオンラインの両方で割引を適用する際、共通の料金計算が窓口専用の入力を要求していると分かったとする。オンライン側に計算式を複製する前に、元の担当者とその入力の意味を確認する。既存の窓口の料金例を保ったまま、どちらの入口からも必要な条件を渡せるようにする。次の割引改定が一か所の変更で済み、両方のテストで結果を確かめられれば、共有が役に立っている。
