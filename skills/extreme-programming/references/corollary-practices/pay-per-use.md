# Pay-Per-Use（利用都度課金）

顧客がソフトウェアを使った分に応じて料金を支払う方式では、どの機能に繰り返しお金を払っているかが、次の開発に投資する手掛かりになる。課金単位が顧客の仕事の完了と対応するか、顧客側でも件数と金額を確かめられるかを一緒に考える。利用回数が単に操作の手間を数えている場合、その数字の増加を価値の増加と解釈すると判断を誤る。[経済性](../principles/economics.md)

## 帳票の発行を一件として数える

有料帳票の発行で通信の再試行が起きたとき、同じ依頼に二度課金すると、請求額と顧客が得た帳票数が食い違う。何を一件とみなすかを決め、発行履歴と請求明細を顧客が突き合わせられるようにする。改善後に支払いを伴う再利用が続くかを見て、顧客にも使った理由を聞く。四半期末にしか発行しない重要な帳票もあるので、投資の判断には利用の周期や代替手段も織り込む。
