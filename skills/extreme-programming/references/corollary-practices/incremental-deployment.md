# Incremental Deployment（インクリメンタルなデプロイ）

稼働中の仕組みを置き換えるとき、一部の業務を新しい仕組みに移し、結果から学んで次の範囲を選ぶ。区切りは窓口、取引の種類、利用者の集団など、旧版と新版のどちらが一つの取引を最後まで扱うかを決められる単位にする。小さい単位で動く状態を保つには、接続部分も含めて頻繁に統合する。[継続的インテグレーション](../primary-practices/continuous-integration.md)

## 一つの窓口を切り替える

一つの窓口で受けた申請だけを新システムに送り、申請番号ごとに記録先を一つに決める。新システムの受付件数と発行した受付票を照合し、取消や再開も通ることを窓口の担当者と確かめる。差異が出たら次の窓口への切り替えを待つ。新規受付を旧版に戻したときも、既に受けた申請の参照先と処理責任は保つ。移した範囲が単独で業務を完結できて初めて、次にどこを移すか判断できる。
