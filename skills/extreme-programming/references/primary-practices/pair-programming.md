# Pair Programming（ペアプログラミング）

二者が同じ変更を進めると、一方が実装に集中している間に、もう一方が要件とテストの食い違いを見つけられる。このスキルを複数エージェントで使うときは、まず受け入れ条件と次のテストを共有する。ドライバーがテストとコードを編集し、ナビゲーターが差分と実行結果を見ながら、次に確かめたい点を返す。

たとえば「満席の回には申し込めない」を実装する。ドライバーがエラー表示のテストを通したら、ナビゲーターは「予約一覧にも申込が残っていないか」と問う。二者で受け入れ条件を読み返し、一覧に変化がないことを次のテストで確かめる。交代するときは最後に通った例と残る疑問を渡すと、次の編集が続けやすい。

ナビゲーターの指摘が完成後にしか届かない場合は、一つ前のテスト結果が出た時点で差分を共有する。単独で進める環境でも、同じ条件とテスト候補を使って[テストファースト](test-first-programming.md)を続けられる。
