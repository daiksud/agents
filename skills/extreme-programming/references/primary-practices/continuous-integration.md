# Continuous Integration（継続的インテグレーション）

各自の変更を短い間隔で共有のコードに取り込み、一緒に動くことをビルドとテストで確かめる。統合の間隔が長いと、単独では正しかった変更同士の前提が食い違い、原因の候補も増える。他の人が取り込みやすい大きさで、途中でも既存の振る舞いを保てる単位に切る。

たとえば送料計算の呼び出し方を変えるなら、最初に新旧どちらの呼び出し方でも同じ金額になるようにする。テストを通して共有のブランチに統合し、続いて呼び出し元を移す。別の人が旧形式を使う配送手段を追加しても、最初の統合で失われない。移行後に、旧形式を使う箇所が残っていないことを確かめて整理する。

統合後の検査が失敗したら、原因を絞って直すか、該当変更を戻して共有のコードを再び使える状態にする。個々のブランチが成功していても統合時の不整合が続くなら、共有する間隔と、組み合わせを確かめるテストを見直す。
