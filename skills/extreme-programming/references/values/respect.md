# Respect（リスペクト）

作業の影響を受ける人には、開発者からは見えない知識や制約がある。異論が出たら、その人が何を守ろうとしているかを聞き、判断に参加できるようにする。ペアの相手が実装を指摘したときも、問題が現れる条件を一緒に試せば、根拠をもとに議論できる。

たとえばサポート担当者が「検索結果に注文番号を残したい」と言い、開発者は画面を簡潔にしたいと考えたとする。担当者に普段の問い合わせを一件たどってもらうと、同姓同名の注文を電話中に見分けるために番号を使うことが分かる。番号を残す案と、必要なときに表示する案を同じ問い合わせで試せる。

どの案なら正しい注文を選べたか、問い合わせ中に何回画面を移る必要があったかを担当者と確かめる。その人の経験を設計に生かし、採った案が困りごとを解決したかまで本人に返す。[Whole Team](../primary-practices/whole-team.md)
