# Feedback（フィードバック）

「この変更で何が変わるはずか」を先に言葉にし、その予想と実際の結果を比べる。疑問によって、答えを得られる相手や場所が違う。計算の正しさは具体例を実行して確かめられる。利用者が結果を理解し、次の操作を選べるかを知るには、その人が実際に使うところを見る。

たとえば予約の重複を防ぐ変更なら、同じ申込みを二度送っても一件しか残らないことを保存先まで含めて試す。次に利用者に試してもらうと、予約は一件でも、応答が遅く完了したか分からず再送していることがある。この観察から、結果の表示を次の変更として選べる。

フィードバックを得る時点は、まだ設計や優先順位を変えられるところに置く。得た結果が予想どおりなら次の例へ進む。違えば、疑っていた箇所を直す前に、どの観察が予想と食い違ったかをペアで特定する。[Test-First Programming](../primary-practices/test-first-programming.md)
