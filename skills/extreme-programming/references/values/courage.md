# Courage（勇気）

実装に費やした時間が長いほど、前提が崩れても予定どおり進めたくなる。勇気が要るのは、分かった問題を関係者に伝え、必要なら作業中の案を手放すときである。判断を変える根拠と、次に取れる小さな行動を一緒に示すと相談しやすい。

たとえば料金計算を一本化している途中で、以前からの契約にだけ異なる端数処理があると分かったとする。該当する請求の例を一件テストにし、今の案ではいくら違うかを示す。担当者に期待額を確かめ、確認済みの契約から切り替えるか、一本化の範囲を見直すかを決める。

取り消せる範囲で試せば、必要な設計変更にも踏み出せる。変更後は、旧契約と新契約の金額をそれぞれ検証する。合意が必要な例は見えるところに残し、次の担当者も「どの契約まで扱えるか」を説明できるようにする。[Baby Steps](../principles/baby-steps.md)
