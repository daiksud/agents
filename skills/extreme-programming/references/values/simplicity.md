# Simplicity（シンプリシティ）

今日求められている振る舞いをすべて満たし、次に読む人がその理由をたどれる設計を選ぶ。判断に迷ったら、各案で「今ある規則を一つ変えると、何か所を理解して直す必要があるか」を試す。数行の重複があっても、それぞれが別の理由で変わるなら、共通化するとかえって条件分岐が増える。

たとえば明細をCSVで出力するとき、まず必要なのは列の順序、区切り文字、引用符の扱いである。既存のCSVライブラリを使い、カンマを含む品名も一列として読めることを例で確かめる。形式を選ぶ設定やプラグイン機構は、今の利用者が使う場面を説明できるようになった時点で検討する。

後からJSON出力が加わり、両形式に「取消済みの明細を除く」という同じ規則が生まれたら、その選別を一か所に置く。列順や引用符はCSV側に残す。二つの出力例を通したまま、片方の表現だけを変更できるかが設計を確かめる手掛かりになる。[Incremental Design](../primary-practices/incremental-design.md)
