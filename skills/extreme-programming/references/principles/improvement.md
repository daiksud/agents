# Improvement（改善）

現在のやり方を出発点に、仕事の結果が一つ良くなる変化を試す。理想像との距離が大きくても、今日の変更だけで全部を埋める必要はない。一方、小さな修正のたびに同じ問題へ戻ってくるなら、その問題を生んでいる設計や作業の分担まで見直す理由になる。

## テストが失敗した後の調査を短くする

受注のテストが失敗しても「結果が異なる」としか表示されず、担当者が毎回デバッガで値を追っているとする。今日触る一例で、どの注文のどの金額が期待と異なるかを読み取れるようにする。過去の不具合を手元で再現し、別の担当者が失敗出力から調査を始められるかを確かめる。同じ読みづらさがほかでも続くなら、共通の比較処理を直す。一例で得た効果と残った不便を、次に手を入れる場所の判断に使う。
