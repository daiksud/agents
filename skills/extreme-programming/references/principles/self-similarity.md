# Self-Similarity（自己相似性）

小さな範囲でうまくいった解き方には、規模を変えて使えるものがある。まず「なぜ効いたのか」を取り出し、いまの問題でもその条件が成立するかを考える。形だけをそろえても、フィードバックにかかる時間や失敗の影響が異なれば、同じ結果は期待できない。

## 一つの関数で効いた照合方法を製品移行に使う

計算関数を置き換えた際、同じ入力に対する新旧の結果を比べると、丸めの違いを早く発見できたとする。請求システムの移行でも、まず一種類の請求について新旧の計算結果を照合できる。ただし、二つのシステムが同時に請求を送ると二重請求になる。新しい側は送信前の明細を作るところで止め、差が出た明細を調べる。比較で移行判断に必要な差を説明できてから、対象とする請求の種類を増やす。
