# Reflection（ふりかえり）

一区切りついたら、期待していたこと、実際に起きたこと、差が生じた理由として考えられることを分けて話す。観察できた事実を共有すると、記憶や役割の違いを手掛かりにできる。うまくいったときも、偶然だったのか、また使える工夫があったのかを調べる価値がある。

## 手戻りの経緯から次の試みを決める

予約の変更期限について、実装後に日付の解釈が違うと分かったとする。最初の説明、テストを書いた時点、利用者が違いに気づいた場面を順にたどる。「要件をもっと詳しく書く」で終えると、誰がいつ何を変えるかが定まらない。次の期限変更では、担当者と開発者が締切直前と締切ちょうどの例を実装前に選ぶことにする。その仕事が終わったときに、例を出す手間に見合う早さで食い違いを見つけられたかを話し合う。
