# Redundancy（冗長性）

影響の大きい失敗には、見逃す理由の異なる対策を組み合わせる。同じ計算式を写したチェックを増やすと、式の誤りまで共有する。どんな故障を一つ目で防げるか、それでも通ってしまうものをどこで見つけられるかを考える。重ねる手間と、発見が遅れたときの影響を比べて範囲を決める。

## 請求の端数処理を異なる観点で調べる

明細の丸め方は、経理と合意した金額例を使ってテストする。しかし各明細が正しくても、請求書を組み立てる段階で一行を二重に取り込むことがある。請求書から元の注文明細へたどり、請求対象の各行が一度ずつ反映されたかも照合する。既知の丸め誤差と行の重複をそれぞれテストデータに入れ、どちらの確認が何を検出するかを試す。片方を通ってしまう誤りをもう片方が捉えられれば、二つを維持する根拠になる。
