# Mutual Benefit（相互利益）

いま変更を頼んだ人、変更する人、次に保守する人がそれぞれ何を得るかを考える。今日の調査を急いで済ませても、次の担当者が同じ条件を一から調べ直すなら、その分の手間が残る。今日の問題を解く過程で、次の人も使えるものを作れないか探す。

## 問い合わせの再現例を修正に使う

請求を取り消したのに翌月の明細に残る、という問い合わせが来たとする。問い合わせ担当者と開発者で、実際に問題が起きる締め日と取消日の組み合わせを特定する。個人情報を除いたその例をテストにすると、担当者は顧客に説明する条件を得られ、開発者は修正をすぐに試せ、将来の変更でも同じ不具合を検出できる。今回の問い合わせに回答できたかと、別の保守担当者がテストだけで条件を再現できるかの両方で利益を確かめる。
