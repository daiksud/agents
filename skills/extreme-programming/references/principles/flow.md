# Flow（流れ）

利用者の要望が、相談、実装、確認、統合を経て、使える変更になるまでをひと続きに見る。各人がそれぞれ忙しくても、途中に待ちが積み上がると、前提の取り違えが分かるのは遅くなる。着手した仕事がいくつも残っているときは、どこで、何を待っているかを最も古い一件からたどる。

## レビュー待ちを減らす

完成した変更がレビューを数日待ち、そのあいだに開発者が次の仕事を始めているとする。一件を一緒に読むと、画面変更とデータ移行が混ざり、確認に必要な人をそろえるのに時間がかかっていた。まずその変更の確認を終え、次は従来の画面でも動くデータ移行を先に統合する。着手から最初の統合までの待ち時間を前の例と比べ、残りの画面変更も利用者に届くまでたどる。待ちが統合の後へ移ったなら、そこで滞る理由を調べる。
