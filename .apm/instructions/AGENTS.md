# インストラクションの作成・更新

このディレクトリの `*.instructions.md` を作成・更新するときに適用する。
構成や記入例が必要な場合は、[汎用テンプレート](../../docs/templates/instructions.md) を参照する。

## 形式

- このディレクトリのMarkdownは [Open Knowledge Format（OKF）](https://github.com/GoogleCloudPlatform/knowledge-catalog/blob/main/okf/SPEC.md) v0.2の概念文書として扱う。
- YAML frontmatterに `type: Instruction` と、先頭の見出しに一致する `title` を記載する。
- ファイル名は対象を表す英単語を小文字のハイフン区切りにし、`.instructions.md` を付ける。
- YAML front matter の `description` に、指示の対象と目的を一文で書く。
- 本文は日本語のMarkdownで書き、先頭の見出しにインストラクション名を付ける。
- テンプレートから目的に必要な節だけを選び、未記入の欄や不要な節を残さない。
- APM用の `description` や `applyTo` など既存のメタデータは保持する。

## 内容

- 一つの箇条書きには一つの指示を、短く、その指示だけで意味が通じる文で書く。
- 適用する条件と行動を明記し、「適切に」「必要に応じて」だけで判断を委ねない。
- 必須の行動は「〜する」、禁止事項は「〜しない」と書く。
- 共通して繰り返し使う基準を残し、個別タスクの依頼内容や進捗を含めない。
- コードから分からない背景、標準と異なる規約、環境固有の注意点を優先する。
- 各行を削除した場合に起こる間違いを考え、必要性のない行や一般論を削る。
- 既存のインストラクションと重複するルールを再掲しない。
- 詳細を別ファイルに分ける場合は、参照する条件とパスを本文に書く。
- 例と強調は誤解や見落としを防ぐ箇所に絞る。

## 確認と見直し

- 記載するパスやコマンドが実在し、説明と一致することを確認する。
- 既存の指示との矛盾や、例とルールの不一致がないことを確認する。
- 手順や完了条件を書く場合は、結果を検証する方法と期待結果を具体化する。
- 代表的な場面に当てはめ、取るべき行動を判断できることを確認する。
- 指示が守られない場合は、追記する前に文章量と曖昧さを見直す。
- 挙動の改善を目的に変更した場合は、問題が起きた依頼で効果を確認し、未確認ならその旨を報告する。
